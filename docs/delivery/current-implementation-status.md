# 当前实现状态｜防止把“目标架构”误认为“已经完成”

> 本文件回答一个问题：**仓库里现在真正已经有代码的是什么，哪些只是目标规格/工程骨架。**

## 状态定义

- ✅ 已有可运行实现：已经存在代码并可用于对应目的；
- 🟡 骨架/Mock：只有接口、路由、页面或假数据骨架，不能视为生产能力；
- ⬜ 尚未初始化：文档已经定义，但代码目录/真实实现尚未完成；
- 🗃️ 历史参考：只保留追溯和视觉/交互参考，不再承载正式业务。

## `services/api` 当前特别说明

现有代码主要用于说明工程形态，不等于接口已完成。例如：

- `GET /v1/topics` 当前可能返回空数组；
- `POST /v1/capture-jobs` 当前只创建内存中的示意 job，没有数据库/队列持久化；
- `POST /v1/script-drafts/generate` 当前返回 503，表示生成服务尚未配置；
- 微信登录、Profile、Benchmark、Transcript、Analysis、Academy 等正式能力尚未全部落地。

因此前后端评估进度时，**不能根据“路由文件存在”判断功能已经完成**。

## 文档与代码发生冲突怎么办

- 文档描述的是**已冻结目标行为/接口**，代码骨架如果与当前文档冲突，应修代码骨架；
- 历史 Demo/Flutter 如果与当前文档冲突，历史实现失效；
- 如果开发认为当前规格技术上不可行，先提 PR/评审修改真源，不要静默按自己的理解实现。
