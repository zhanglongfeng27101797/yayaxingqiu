# 微信小程序平台边界｜V1 开发必读

> 目的：防止把旧 Android/App 能力、浏览器能力或后端能力误认为小程序前端可以直接完成。

## 1. 正式前端能力边界

小程序负责：

- 页面与 TabBar；
- `wx.login` 获取临时 code；
- 业务 API 调用；
- 链接输入/粘贴后的任务创建；
- 草稿编辑与轻量本地缓存；
- 采集/逐字稿/分析任务状态展示与恢复；
- 小程序内提词器；
- 微信平台允许的分享、授权、文件/媒体交互。

小程序**不负责**：

- 第三方平台链接解析核心逻辑；
- 长时间媒体下载/转码/ASR/AI分析；
- 保存第三方平台或模型服务的密钥；
- 跨 App 悬浮窗；
- 系统级后台常驻任务；
- Android/iOS 原生权限能力；
- 把旧 WebView DOM/localStorage 代码直接搬进正式工程。

## 2. 采集爆款

正式交互是：用户主动粘贴/输入链接 → 小程序提交 URL → 服务端创建异步任务 → Worker 解析/转写/分析 → 小程序按 jobId 恢复和展示结果。

不要实现成：

- 小程序持续后台监听其他 App；
- 小程序直接在前端长期下载、解析第三方视频；
- 依赖旧 APK 的 WebView 模拟逻辑；
- 固定 Demo ID 覆盖上一条采集。

## 3. 提词器

V1 只做“小程序内提词器”：

- 开始/暂停；
- 字号；
- 慢/中/快三档速度；
- 镜像；
- 重置。

不做跨 App 悬浮、不接管系统相机、不做美颜、滤镜、剪辑。

## 4. 长任务

采集、ASR、视频拆解必须由服务端任务系统执行。前端只负责：

1. 创建任务；
2. 保存 jobId；
3. 展示状态；
4. 页面离开后不阻塞服务端处理；
5. 再次进入时查询并恢复结果；
6. 对可重试错误提供重试入口。

不要使用“前端页面必须一直打开”作为任务完成前提。

## 5. 登录与密钥

- 小程序只获取 `wx.login()` 的临时 code；
- code 交给自有后端；
- AppSecret、session_key、第三方解析密钥、ASR/AI密钥不进入小程序代码；
- 小程序使用自有后端签发的业务会话访问 API。

## 6. 数据真值

可以本地缓存：

- 编辑中草稿临时副本；
- 未提交表单；
- 最近任务 ID；
- 提词器偏好；
- 轻量筛选状态。

正式真值以服务端为准：

- 用户资料；
- Topic；
- Benchmark；
- Transcript；
- Analysis；
- 正式 ScriptDraft；
- 商学苑内容；
- 用户权益/账号信息。

## 7. 旧 Demo 的迁移原则

旧 APK/WebView 代码只能回答“早期大概想怎么展示”，不能回答“小程序应该怎么实现”。

尤其不要照搬：

- `document.querySelector` / DOM 渲染方式；
- browser `localStorage` 作为正式数据层；
- WebView fixed bottom nav 作为小程序 TabBar 实现；
- Android 返回键逻辑；
- Demo Toast 占位；
- 假进度条与假采集结果。

## 8. 技术栈冻结

M0 评审时确定：

- 默认：微信原生小程序 + TypeScript；
- 或公司已有成熟标准：Taro / uni-app。

一旦确定，在同一正式前端工程内不要混用多套框架；变更需更新 `source-and-decisions.md` 并评审。
